# 価格履歴と参考指標

2026-09-26。価格の検証基盤を実装。売買ルール・ニュース分析・収益性の評価は未実装。

## 取得と保存

- Alpaca SIPの日足を過去400暦日分取得。NYの当日は丸ごと除外し、分割調整済みの確定終値を使う。配当調整は含まない。
- Paper APIの読み取り専用カレンダーで取引日を照合。両銘柄の欠損・日付重複・日付不一致・未完了ページを拒否。注文APIは使用しない。
- カレンダー、SOXL、TQQQ、検証結果の反映を別リクエストに分割。手動ボタンは順に実行し、開始は1時間3回まで。定期実行は有効時のみJST 9/15/21時から5分ごとに4段階で実行し、各時15分頃に反映。通知送信と重なる回はデータ処理を見送る。
- 全期間を一つのJSONとしてDBトランザクションで置換する。古い取得が後から完了しても新しい記録を上書きしない。
- 取得開始時刻・取得完了時刻・提供元・通貨・調整方式・フィード・計算版・入力ハッシュを記録。
- 各市場日付で最初に保存できたスナップショットを365日間保持。それ以降は削除。最新スナップショットは別に保持する。
- 認証済みAPIでだけ表示。実価格の履歴や保有情報を公開リポジトリに保存しない。
- 新しい版で取得に失敗したときは以前の履歴を保持し、指標の表示を保留。保存カレンダーの最新確定取引日に追いついていない場合も表示しない。

保存開始以前の履歴は、現在の提供元が返した調整済みデータである。過去にその情報が実際に参照可能だったことを証明するデータではなく、そのまま先読みのないバックテスト実績として扱わない。ページ間の提供元側の同時性も保証しない。

## 計算契約 `close-indicators-v1`

| 表示 | 計算 |
| --- | --- |
| SMA20 / 50 / 200 | 直近N取引日の終値の算術平均。N本未満ならnull |
| RSI14 | 最初の14差分の平均上昇・下落を種としてWilder平滑化。15本未満ならnull。全て同値は50、上昇のみ100、下落のみ0 |
| 20取引日の価格変化率 | `(最新終値 / 20取引日前終値 - 1) × 100`。21本必要 |
| 63取引日の最高終値からの下落率 | `(最新終値 / 直近63本の最高終値 - 1) × 100`。最新を含む。期間中の最大ドローダウンではない |

RSIは各スナップショットの先頭で初期化するため、無限の全履歴から計算した値とは微差があり得る。指標はETF自身の値動きの記述であり、上昇確率・買い時の推奨・基礎指数の指標ではない。

## 検証

- ローカルとCloudflareの双方で各275営業日（2025-08-22〜2026-09-25）を取得し、カレンダーと一致。
- 指標の独立した数値例、ウォームアップ本数、上昇・下落・横ばい、欠損と重複、ページ上限をテスト。
- ローカルWorker+D1で所有者制限・古い指標の非表示・更新順序の保護を確認。
- 本番CPUはログ配信の `cpuTime` で測定。待ち時間を含む `wallTime` と区別する。
- 一体処理の初回14ms、軽量化後12〜13msを確認し、カレンダーと価格更新を分割。さらに銘柄単位と反映処理へ分割し、最終版の本番計測でカレンダー5ms、SOXL取得6ms、TQQQ取得7ms、反映4msを確認。最終画面からの再測定は順に4・10・4・4ms。少数サンプルであり、上限ぎりぎりの回もあるため継続測定は必要。反映時のDB書き込み8行、DB全体212,992 bytes。
- 無料枠での長期安定運用、アカウント全体の請求・利用量、分割処理の継続検証は別途必要。

本運用設定では分割した定期取得を有効化し、最初のCron発火（CPU 7ms）を確認。全段階が定刻で完了する継続実証は別途必要。公開テンプレートは安全な初期値として無効のまま。自動売買シグナルやニュース通知はまだ送らない。
