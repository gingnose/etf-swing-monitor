# SOXL / TQQQ Swing Monitor — 実装計画案

状態: 2026-09-26、初版のユーザー方針を確定。技術実証事項は第2節。P1接続確認版を実装。クラウド配置・実データ取得・Androidでのインストールと予約通知到着を確認済み。価格履歴・参考指標・資金保有台帳も実装（[台帳仕様](PORTFOLIO.md)）。詳細は [DATA_PHASE.md](DATA_PHASE.md)。価格条件2仮説の表示・過去イベント分析・初回観測保存を追加（[仕様](PRICE_RULES.md)）。条件一致から買い通知への昇格は未実施。ニュース取得・出所表示・見出し分類を追加（[仕様](NEWS.md)）。本文AI分析・真偽判定・追加効果の実証は未完了。無料枠の継続計測などは未完了。詳細は [P1_STATUS.md](P1_STATUS.md)。
公開先: https://github.com/gingnose/etf-swing-monitor
コードはMITライセンスで公開。稼働アプリと運用データは所有者専用。

## 1. 確定している要件

- SOXLを主対象、TQQQを副対象とする。
- 数週間のスイングを想定。含み損で保有を継続する場合は期間が延びることを評価にも反映する。
- ニュース・価格・市場環境を調べ、購入、買い増し、保有継続、利益確定などの判断材料を示す。
- 楽天証券で手動売買し、購入・売却をアプリへ登録する。自動注文は初版の対象外。
- 固定下落率での損切りと、含み損での売却候補を出さない。情勢悪化時は悪材料・購入前提の変化・買い増し停止を表示する。利益確定候補の表示範囲は確認中で、回答までは売却候補を実装しない。
- AndroidのPWAで利用し、PCの常時起動を必要としない。
- 自動通知は日本時間の1日につき最大1件。SOXLとTQQQを1件へまとめる。
- 月額サービス料金0円を必須とし、無料枠不足時は処理を削減・停止する。
- ソースコードをGitHubの公開リポジトリとして管理する。

## 2. 確定した初期設定と技術実証事項

- 初回起動時に購入待機資金とSOXL/TQQQの既存保有を入力する。
- 利益判定は米ドル建て。取得原価と推定売買費用を含める。円換算損益は参考表示し、米ドルで利益でも円で損失となる可能性を区別する。
- 月額サービス料金0円を必須とする。有料プランへの切替や従量課金を行わず、無料枠で不足する処理は削減・停止する。
- 無料でニュース分析に必要な品質を得られない場合は未達を明記し、収益性や精度を実証済みと表示しない。

毎月の積立は購入待機資金を増やす仕組みとして扱う。個人の実際の積立額、現在残高、保有情報は公開文書へ記載せず、非公開設定へ保存する。
積立予定と実際の入金を区別し、予定だけで購入可能残高を増やさない。買い増しは確認済み残高の範囲に限定する。
円の待機資金とドルの待機資金を別々に記録し、両替時のレートと手数料を記録する。実購入可能額は両替費用を含めて計算する。
アカウント作成・APIの利用資格・Cloudflare接続は実証工程で確認する。キーやトークンはチャットや公開リポジトリに貼らず、デプロイ先のsecretとして登録する。
ライセンスはユーザーからの選定委任に基づきMITを採用。

技術実証後に確定する事項: データ提供元の無料利用権限、認証方式、無料対象AIモデルと品質、CPU制限内での実行方法、Android実機の通知動作。

## 3. 優先順位と完了条件

### P0: 要件確定とプロジェクト分離

- 未確定事項を回答に基づき決定記録へ反映。
- gingnose配下へPublicリポジトリを作成。既存ゲームの履歴やファイルは持ち込まない。
- README、docs/IMPLEMENTATION_PLAN.md、docs/DECISIONS.md、.gitignore、プレースホルダーのみの.env.exampleを用意。
- 本人の保有情報、予算、DB、APIキー、ニュース本文はコミットしない。
- コード公開とアプリ公開の範囲を明記。サンプル画面は架空データを使用。
- 完了条件: リポジトリURLと合意済み要件が確認できる。

### P1: 技術・費用の実証（画面を作り込む前に実施）

- Alpaca無料アカウントでSOXL/TQQQの日足・必要履歴を実取得し、権限、遅延、市場カバレッジを記録。
- IEXと市場全体の出来高を混在させない。価格調整、分割、取引日、欠損データを確認。
- ニュースAPIの無料権限、取得本文、履歴、保存・利用条件を確認。公式RSSなども候補として比較。
- クラウドの定期処理 → 保存 → Androidへのテスト通知まで最小限で接続。
- 所有者認証を先に設ける。利用者制限は画面だけでなくAPIで強制。
- Samsung実機で画面を閉じた状態、ロック中、再起動後、通知許可の取り消しと再登録を確認。
- 無料枠でのCPU時間、通信回数、AI使用量を測定。Cloudflare採用は実測で確定。
- 完了条件: PC停止中にクラウドから端末へ通知が届き、無料枠で実データ取得が動く。
- 失敗時: データ提供元や実行基盤の変更案を示す。課金は自動的に開始しない。

### P2: データ保存とニュースなしの比較基準

- 価格、ニュース公開時刻、初回取得時刻、更新時刻、情報源を保存する。
- 判断エンジンはWeb画面やAIから独立した純粋な計算モジュールにする。
- 最初の戦略候補は少数に限定: 上昇傾向での押し目、下落後の回復確認、過熱と勢い低下による段階的利確。
- パラメーター、想定期間、入力データ、ルール版を判断ごとに記録。
- 買い増しは新規購入条件と予算制約の両方で判断。価格下落だけでは勧めない。
- SOXLとTQQQを合算した保有額と集中度も扱う。
- 利確候補は、米ドル・取得原価・推定売買費用に基づく利益条件を満たす場合だけ許可する。前提データ不足なら利確判断を保留する。注文時の値動きによる損失回避までは保証しない。
- 含み損時の売却候補抑止はAIから独立したルールで強制する。ニュース分析がこの条件を上書きしない。
- 完了条件: 同じ入力・同じルールから同じ判断を再現できる。

### P3: 検証基盤と最初の成績評価

- 過去データを時間順に設計用・検証用へ分割。試した条件の数と変更履歴を残す。
- 通知時点で取得可能だった情報のみを使用し、通知後の次の売買可能時点で約定を仮定する。
- 予算と買い増し回数を有限にし、手数料・スプレッド・通知後の遅れを含める。
- 分割調整と実際の約定価格の整合性、同じ日足内の利確到達順序の不明確さを処理する。
- 保有継続、価格戦略、価格＋ニュース戦略を同じ資金・コスト条件で比較できるようにする。
- 指標: 含み損益込みの総資産推移、最大下落、実現利益、資金拘束期間、投入額、取引件数。
- 損切りなしの未決済ポジションを除外して勝率を算出しない。
- 重い過去検証は開発時のローカル実行または別の検証ジョブで行い、日常監視の無料Workerに押し込まない。
- 完了条件: 再実行可能な評価レポートがあり、結果に応じて採用・修正・見送りを判断できる。

### P4: ニュース分析の追加と増分効果の検証

- 記事の重複、転載、古い記事の再配信をまとめる。
- 公式資料、報道、未確認情報を区別し、独立した情報源か確認する。
- AIは事象、関連銘柄、影響経路、根拠URL、不明点を構造化して返す。
- 信頼できる出所であることと、株価の方向予測の確かさを分ける。
- 市場予想データがない場合は予想との差を推測で補わない。
- ニュース本文は外部データとして扱い、そこに書かれた指示でツールや設定を操作させない。
- まず買い見送り、買い増し停止、利益確定理由の補助として評価する。
- AIの自己申告の自信を上昇確率として表示しない。数値確率は別途校正できるまで使わない。
- モデルの過去知識による検証汚染に注意し、実時間の前向き記録を必須にする。
- 完了条件: 価格だけの判断との差とその結果が追跡できる。効果が確認できなければニュースは参考情報に留める。

### P5: Android向けアプリの完成

PWAを採用し、React + TypeScriptの軽量な画面を候補とする。バージョンは実装開始時に確認して固定。

- 今日の判断: SOXL優先、TQQQ、判断時刻、価格時刻、根拠、無効となる条件。
- 保有: 購入・売却・買い増し、手数料、保有数量、平均取得価格、履歴訂正。
- 根拠と履歴: 使用指標、関連ニュース、判断変更、実現・未実現損益。
- 設定: 予算、通知時刻、通知テスト、損失時の方針、監視停止。
- 株式分割、一部売却、入力訂正に対応。利益通貨と税の扱いを明記する。
- 購入理由を保有データへ関連付け、後のニュースで前提が崩れたかを評価。
- データ出力と復元、ログアウト後のキャッシュ保護、古いデータ表示を実装。
- 完了条件: Androidだけで売買記録と判断確認を行える。

### P6: 通知運用と前向き評価

- 1日の自動通知はJST基準で最大1件。重大ニュースでも勝手に例外を設けない。
- 初期通知時刻は日本時間21:00。状態に変化がなければ送らない。時間選定はユーザーの委任に基づく初期設定で変更可能。収集回数と通知回数は分離する。
- 複数ジョブや再試行で二重送信しないよう、送信予約とIDをDB管理し端末側も重複抑制。
- 送信結果が不明なときは無条件に再送しない。通信断では到着時刻や厳密な一回配信は保証できない。
- データ欠損、分析失敗、AI上限到達は「判断不能」とし、前日の買い判断を最新として流用しない。
- アプリに最終正常実行時刻と障害状態を表示。日次通知枠の中で必要な障害情報をまとめる。
- 実時間で仮想判断を先に保存してから結果を記録。期間だけでなく取引件数と相場環境を見て評価する。
- 完了条件: スケジュール、通知上限、保有記録、障害時動作が実機・クラウドで確認できる。
- 収益性が未確認でも実験用アプリとして公開可能だが、実証済みと表現しない。

## 4. 暫定構成

Android PWA → 所有者認証付きAPI → D1（非公開データ）
定期ジョブ → 価格/RSS/API → 正規化 → 数値ルール + 記事分析 → 判断保存 → Web Push

Cloudflare Workers / D1 / Workers AIを候補とする。無料CPU枠・モデル制約・配信実装の実証後に確定。
GitHubはソースコード、架空サンプル、ドキュメント、テスト、ビルド用。秘密情報と運用DBは置かない。

## 5. 主な検証項目

- 計算: 買い増し、一部利確、分割、コスト、入出金と予定積立の区別、予算上限、将来情報の混入防止、含み損時の売却候補抑止。
- 取得: API制限、欠損、古いデータ、重複ニュース、記事更新、休日と夏時間。
- AI: 根拠のない断定、関連性誤判定、構造化出力失敗、同一入力の変動。
- 保護: 未認証アクセス拒否、秘密情報のフロント混入防止、実データの公開防止。
- 通知: 日付境界、同時起動、再試行、端末再登録、オフライン、通知拒否。
- 運用: 無料枠到達時停止、監視停止表示、バックアップ復元。
