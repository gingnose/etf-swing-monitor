## 技術実証で確認する事項

データ無料利用権限、所有者認証、無料AIの品質、実行枠、Android実機の通知動作。

## 技術候補（採用確定ではない）

React / TypeScript、Cloudflare Workers / D1 / Workers AI、Web Push、Alpaca Basic。
データの利用権限・無料枠・Androidでの動作を実測して確定する。認証方式もP1で選定し、全APIで所有者制限を検証する。

## 公開文書の方針

個人の実際の積立額・給与・資産・保有情報・認証情報を記載しない。実データやライセンスで再配布できないニュースはコミットしない。

## P1実装での選択

- 所有者が持つランダムキーでログインし、HttpOnlyセッションを使用。キーそのものはDBに保存しない。
- キーは初期セットアップで作成し、公開画面やクライアント配信物に含めない。
- 個人用1端末のWeb Push。通知予約は約5〜10分後、JSTの自動通知上限に含める。手動の即時テストは別枠で1日5回まで。
- 価格は当日NY日付を除外した日足、SIP・分割調整。認証エラー時に取得元を勝手に変更しない。
- 定期価格取得は初期状態で無効。所有者の無料アカウントでCPU時間と利用枠を実証してから有効化する。
- ニュース分析と取引ロジックはP1に含めない。接続確認画面にも売買シグナルを表示しない。

## 価格履歴フェーズ

- 400暦日の日足を取引日カレンダーと照合。指標は説明用の数値に限定し、買い・売りの通知へ変換しない。
- CPUを分散するため、カレンダー・SOXL・TQQQ・反映を別リクエストで実行する。定期実行はJST 9/15/21時から開始し各時15分頃に反映。
- 売却候補の表示範囲に会話上の曖昧さがあるため確認中。回答を得るまでは売却ロジックを追加しない。

## 資金・保有台帳フェーズ

- 円・米ドルの実残高、既存保有の数量と取得総額を初回に入力する。月次予定は残高に自動反映しない。
- 入出金・実両替・売買・分割を手動記録し、訂正・取消・復元では履歴を再計算する。株式の時価評価や売買候補は追加しない。
- 小数の整数演算、履歴中の残高不足検出、更新番号とリクエストIDで二重保存を防止する。詳細は [PORTFOLIO.md](PORTFOLIO.md)。

## 価格ルール検証フェーズ

- 購入金額は本人が決める。待機資金に対する割合制限の提案は採用せず、自動購入額を出さない。
- 押し目・回復確認の2仮説を固定し、価格条件と実用の購入判断を区別する。初回の過去検証では有効性を確認できていないため、買い通知には使わない。
- 詳細は [PRICE_RULES.md](PRICE_RULES.md)。ニュース追加と資金制約込みの検証は後続工程。
