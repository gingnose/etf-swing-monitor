# 無料アカウントでの接続実証

現在は **接続確認と価格履歴の検証** の段階です。売買判断、資金管理、ニュース分析はまだありません。
ローカルの自動テストと、実際の外部サービス・Android通知の実証は別です。

## 1. 必要なアカウント

- [Alpaca](https://app.alpaca.markets/signup): 個人向けの無料Basic / Paper環境で、価格データ用のAPIキーを用意します。入金や有料データ購読は、このアプリのセットアップ手順には含みません。居住地・登録条件によりキーを取得できない場合は作業を止め、別のデータ取得元を検討します。
- [Cloudflare](https://dash.cloudflare.com/sign-up): Workers FreeとD1の無料枠を利用します。Workers Paid、追加課金サービス、独自ドメイン購入は不要です。すでに有料アカウントの場合は、本手順だけで請求0円を保証できないため、無料プランを確認してから進めてください。

APIキー、所有者キー、トークンをGitHub、Issue、チャット、スクリーンショットに貼らないでください。

## 2. ローカル起動

Node.js 24以降を使用します。

```sh
npm ci
npm run setup
```

以下の非公開ファイルが生成されます。スクリプトは既存ファイルを上書きしません。

- `.dev.vars`: 所有者キーのハッシュ、通知用の鍵、Alpacaキーの入力欄。
- `private/owner-token.txt`: アプリにログインするための所有者キー。

`.dev.vars` の `ALPACA_API_KEY` と `ALPACA_API_SECRET` に、無料アカウントで発行したキーをローカルのエディタで入力します。Alpacaのキーをブラウザ画面へ渡す実装にはしていません。

```sh
npm run dev
```

表示されたlocalhostのURLを開き、`private/owner-token.txt` の値でログインします。
Alpacaアカウントが未作成でも画面・認証を確認できます。価格カードにはダミー価格を表示しません。

「データ取得を確認」で、SOXLとTQQQの日足の取得を確認します。デフォルトは `sip`（全市場）かつ当日NY日付を除外した履歴です。SIP権限を取得できなければエラーとし、IEXへ黙って切り替えません。IEXを使う場合は `wrangler.jsonc` の `ALPACA_FEED` を明示的に変更し、出来高の対象範囲が異なることを記録します。

画面を起動せずに実データ接続だけを検証する場合:

```sh
npm run probe:market
```

必要な場合だけ `npm run probe:market -- iex` と明示してIEXを検証できます。SIPとIEXは別の取得元であり、市場全体の出来高として混同しません。結果は非公開の `private/market-probe.json` に保存します。

Alpacaの無料利用権限は実際のアカウントで検証が必要です。本実装はデータ取得のみで、証券会社への注文APIを呼びません。

## 3. クラウドへ配置

アカウント作成とログインは本人が行います。

```sh
npx wrangler login
npx wrangler whoami
npx wrangler d1 create etf-swing-monitor
npm run deploy:prepare -- <作成結果のdatabase_id>
npm run deploy
npm run secrets:upload
```

`deploy:prepare` は無視対象の `wrangler.deploy.jsonc` に実DBのIDを保存します。公開設定にあるゼロのIDはローカル用プレースホルダーです。
`secrets:upload` は `.dev.vars` から必要な値だけを読み、標準入力経由でCloudflare Secretsへ送ります。値をコマンド引数やログへ表示しません。
初回デプロイとSecrets登録の間は、APIが未設定エラーで閉じた状態になります。公開URLのログイン画面には個人情報はありません。

このスクリプトは有料プランへの変更を行いません。ただし、アカウントが実際にFreeであることと、リソース使用量はCloudflareダッシュボードで確認してください。

`workers.dev` のHTTPS URLをAndroidのChromeで開き、所有者キーでログインします。APIは全て所有者認証が必要です。所有者キーは推測困難なランダム値であり、この値を持つ人はログインできるためパスワード相当として管理してください。

## 4. Androidで通知を確認

1. Chromeのメニューからホーム画面への追加／アプリのインストールを行う。
2. アプリで「通知を有効にする」を押し、通知を許可する。
3. 「テスト通知を送る」で通知の到着を確認する。
4. 「通知を予約して閉じる」を押し、画面とPCを閉じる。
5. 約5〜10分後にSamsung端末へ届くか確認する。初回のCron設定反映には遅延がある場合があるため、反映後に実施する。

通知サービスの送信受付は、端末への到着確認とは異なります。ロック状態、再起動後、通知の解除・再登録も別途確認します。
Androidの省電力や通知設定により遅延する場合があります。画面を閉じることと、OS設定からブラウザを強制停止することは同じ条件ではありません。

予約テストも自動通知の1日1件（JST）の上限に含めます。ボタンから明示的に送る即時テストは別枠で1日最大5回です。通知先は1端末です。
到着が不明な送信を自動再送しません。予約が30分以上遅れた場合は破棄します。
通知はこの段階ではテスト文面だけです。定期売買シグナルはまだ送信しません。

## 5. 定期データ取得

無料枠の測定が終わったら、非公開デプロイ設定の `ENABLE_SCHEDULED_CHECKS` を `"true"` にして再デプロイします。JST 9時・15時・21時からカレンダー、SOXL、TQQQ、反映を5分ごとに実行し、各時15分頃に完了します。初期状態では無効です。
Cronは5分間隔で予約通知の有無だけを調べます。実データ取得は上記の段階に限定し、同じ段階の再実行をDBで抑止します。通知を処理した回は価格収集を見送り、翌回以降の完全な収集を待ちます。
本番Cronはクラウドで動きます。`wrangler dev` ではCronは自動実行されません。
接続実証用の実行履歴は30日で削除します。価格の最新スナップショットは維持し、各市場日付の最初の観測を365日保持します。

## 6. 無料枠と未達の扱い

- WorkerはCPU時間10msというFreeの制約に収まるか、本番実測が必要です。ローカルの実行時間で代用しません。
- 超過時は処理を分割・削減し、必要なら機能を停止します。有料化で解決しません。
- 本段階ではAIサービスを呼びません。ニュース分析と無料AIの品質検証は後続です。
- 一定の期間・件数で実測するまでは「無料で安定運用できた」とは扱いません。
- 無料枠の使用状況は、同じアカウントの他のアプリと共有される場合があります。

## 7. 検証コマンド

```sh
npm run check
npm run test:browser
```

`check` は型・単体・ビルド・Worker/D1統合テストです。隔離したローカルDBと偽の資格情報を使い、実際のAlpaca・通知サービスへ接続しません。
`test:browser` は同じローカル実行環境に対しChromeでログインや表示を確認します。ブラウザがない環境では `npx playwright install chromium` を先に実行します。
外部接続やAndroid実機テストが未実施なら、その項目を完了にしません。

## 資産台帳の初回入力

アプリを更新し、所有者ログイン後の「資産台帳」から開始日、円・ドル現金、既存保有の数量と取得総額を入力します。これらはチャットやGitHubには記載せず、アプリ内だけで保存してください。毎月の入金予定は任意で、実入金を記録するまでは残高に加算しません。

既存デプロイへの追加は `npm run deploy` で `0007_portfolio.sql` を適用します。既存の価格履歴、所有者セッション、通知設定は保持します。本番の台帳をテスト値で初期化しないでください。計算・訂正・JSON書き出しの制約は [PORTFOLIO.md](PORTFOLIO.md) を参照してください。
