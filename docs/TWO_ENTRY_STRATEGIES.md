# 2系統の購入候補とニュース・出口の設計

状態: 2系統の参考指標・ニュースの支持/反対・未確定の出口方針を表示に実装。売買通知と実際の出口判定は未実装。過去のσモデルは比較対象として残し、次期の中心を以下の2系統に変更する。利益の優位性は未確認。

## 1. 20営業日高値更新

- 当日の確定・分割調整終値が、当日を除く直前20営業日の最高終値を厳密に上回ること。同値は更新ではない。場中高値ではない。
- 更新幅、条件成立日、データ時刻を表示。連日の高値更新を毎回別の購入推奨として通知しない。再通知条件は検証前に別途固定する。
- 価格条件と出口計画を同じカードに表示。価格条件が成立しただけで勝率や期待利益を断定しない。
- 良材料の裏付けを確認し、裏付けがある候補は「高値更新＋良材料の裏付け」として区別する。良材料なしは「裏付け未検出」であり、悪材料ありとは異なる。
- 安さは説明情報で、20日高値更新に対する必須条件にはしない。

## 2. 長期の低価格圏

- 直前756営業日（約3年）に対する価格順位が下位10%以下を、合意した長期安さの検証候補として使う。定義は PRICE_POSITION.md に従う。
- 厳密な3年安値更新とは区別する。1年・3ヶ月の順位も参考表示する。
- 長期回復や安全性の保証として扱わない。悪材料・ニュース不足・追加下落と待ち時間を併記。
- 価格取得を1200暦日に延長。756営業日分に足りない間は「履歴不足」とする。短い期間で3年順位を代用しない。
- 両系統が同時成立する可能性を許容し、排他的な分類や重複通知にしない。

## ニュースの役割

UIは価格条件、支持材料、反対材料、情報不足を独立して示す。支持と反対を相殺した単一の買い点数にしない。良材料による上乗せの有効性は未検証なので、架空の上昇確率や倍率をつけない。

支持材料の候補は、銘柄・関連企業/業界との関連があり、公開時刻と取得時刻が明確な、業績見通しの引き上げや規制緩和などの具体的な出来事。価格が上がったこと自体を説明する記事や、目標株価引き上げ・憶測・重複配信を独立した根拠として数えない。好決算・利下げ等は一律に好材料とせず、市場予想との差や文脈を取得できなければ方向不明とする。

現状のニュース処理は見出しのルール分類であり、本文・真偽・織り込みの確認を行っていない。その制約を支持材料にも明示する。公式発表等へのリンクと対象銘柄への関連理由を表示する。新しい記事でも古い事実の再掲なら、公開時刻だけで新規材料と判定しない。不明なら新規性不明として扱う。

表示例（実データではない）:
- 価格: 20営業日高値更新
- 支持: 関連企業の業績見通し引き上げを示す見出し／出所・日時／関連理由
- 反対: 検出した懸念を別に表示
- 情報状態: 取得範囲・鮮度・本文や織り込みの未確認
- 出口: 購入時に選んだ出口仮説と現在の状態／未設定なら未設定

良材料だけの通知は作らない。将来の購入候補通知に添える裏付けとして使う。既存の重大悪材料通知とJST1日1回の枠を共有する方針を維持。購入・売却通知の本番有効化は未実施。

## 20日高値更新の出口

従来どおり損切りなしを維持。変更の回答がないため、損切り許容へ変更しない。

共通して比較する研究用仮説:
- +20% / +30%での固定利確。
- 利益域に入ってから上昇を追い、反落で売却候補にする方式。開始利益と追随幅は未決定。過去の最高値で売れたものとしない。
- 20営業日経過は再評価の時点。未合意の強制売却条件にはしない。
- 重大な悪材料が発生したら価格条件が維持されていても出口再評価。良材料が悪材料や情報不足を打ち消す扱いにはしない。

利益判定は既存の希望どおり米ドル基準。売却候補を出した後の窓開け・約定価格で損失になり得るため、利益を保証する「損なしの追随売却」とは説明しない。

同じETFの買い増しが混ざるため、購入の理由・候補ID・出口方針と購入記録を対応づける。現行台帳は銘柄別の平均取得原価で集計するため、戦略別購入分の利益と保有全体の利益を区別する設計が必要。既存保有に購入理由を推定で割り当てない。売却対象数量と利益基準が決まるまでは実際の売却候補を生成しない。

## 検証と実装の順番

1. 本書で入口・ニュースの支持/反対の役割を固定。出口の損切り方針を確認する。
2. 756営業日以上の入力を確保し、未来情報を使わない2条件の計算と欠損処理を実装。SOXL/TQQQは別々に成績を記録する。
3. 出口仮説を固定し、損切りなしの場合の未売却分も時価評価して比較。実現利益だけでなく総資産、保有日数、資金不足で逃した機会を記録する。購入額を自動決定しない。
4. 支持材料を含むニュース状態を表示し、初回取得時刻を保存して前向きに観測。現在のニュースを過去の価格に後付けしてニュース併用の成績にしない。
5. 候補表示、購入記録との対応、出口表示を統合。その後に日次上限と重複抑制を備えた通知を検証する。

月額0円、購入額は本人判断、自動発注なしを維持する。

## 実装の状態

entry-strategies-v1 は新しい参考指標。旧価格モデルの観測と実績は折りたたんで残し、新指標の過去成績として表示しない。新指標の毎日の初回観測保存はまだ追加していない。発生頻度は画面の取得履歴における更新日数と、連続更新日のまとまりを分けて表示。まとまりは独立した購入機会や通知回数ではない。

ニュース支持は直近24時間の重要な具体的な好材料見出しを分類し、eventKeyで重複を抑制。情報源の不足時は支持扱いを保留。本文・新規性・織り込みは未確認として明記する。良材料単独の通知は追加しない。

無料枠のCPUを抑えるため、参考指標と発生頻度は所有者認証されたAPIから受け取る確定終値を使って端末側で計算する。価格取得・カレンダー照合・鮮度判定・既存通知はクラウドで継続する。現在の2系統は表示用で、アプリを閉じた状態の新しい購入通知を実装したものではない。
