# 資金・保有台帳

所有者ログイン後の「資産台帳」で、開始時点の円・米ドル現金、既存保有、毎月の入金予定を入力します。個人の金額は公開コードに設定しません。初期状態は未登録です。

## 記録と計算

- 入出金、実際の両替、買付、売却、株式分割・併合を手入力します。証券会社への注文や自動連携ではありません。売却の記録機能は、売却候補の提案とは別です。
- 毎月の入金予定は目安です。月が変わっても現金を増やしません。実際の入金を記録した時だけ残高が増えます。
- 円現金と米ドル現金は別管理です。円を保有していても、自動的にドルの買付余力とはみなしません。円貨決済の場合も、約定明細の実際の支払額・受取額を使って両替、買付の順に記録します。
- 開始日は、その日に記録する取引の**前**の状態です。開始時点の保有株取得総額は、開始現金から差し引きません。
- 買付では約定総額＋手数料をドル現金から引き、同額を取得原価に加算します。売却では約定総額−手数料を現金に加えます。
- 取得原価は移動平均方式。部分売却の原価をセント単位で四捨五入し、全売却では残った原価を全額除きます。平均取得単価は小数4桁表示です。実現損益は開始後の米ドル集計で、税務申告用ではありません。
- 株式分割・併合では取得総額を変えず、数量を変更します。小数6桁で表せない端株処理は拒否します。分割の自動検出・端株換金の自動処理はありません。
- 日付は日本時間の暦日で、開始日より前・未来の日付は登録できません。日付順、同日なら初回登録順に計算します。訂正しても同日の登録順は変わりません。

JPYは整数、USDは小数2桁、数量は小数6桁。内部は整数演算で端数を管理します。訂正・取消・復元を含めて全履歴を再計算し、途中の現金不足や保有数超過を拒否します。取消済みも含め台帳は500件までです。また、訂正や予定額の変更を含む更新全体は10,000回までです。上限到達後も読み取りとJSON書き出しは利用できます。これを超えるアーカイブや移行は未対応です。

## 保存・プライバシー

データは所有者認証の必要なD1に保存します。APIはキャッシュ禁止で、ブラウザのlocalStorageやService Workerに台帳を保存しません。JSON書き出しは明示的な操作時のみで、アップロードによる復元は未対応です。

更新番号で他の画面との競合を検出します。保存リクエストには一意のIDを付け、通信失敗時は同じ内容・同じIDで再試行します。D1の原子的なバッチで台帳と受付記録を同時保存し、二重反映を防ぎます。台帳画面を閉じて再度入力する前には最新状態を確認してください。再試行情報はブラウザのメモリに限ります。

訂正・取消後も、更新受付の記録をD1に保持します。取消は計算からの除外であり、個人情報の消去ではありません。資金情報を一般公開するAPIはありません。

## 検証範囲

55件の単体・実SQLテスト、ローカルWorkerとD1での認証・API検証、Chromeの320〜1280px幅での操作確認が成功しています。台帳については初回登録、全取引種別、訂正・取消・復元、残高不足、JSON書き出し、ログアウト後の消去を確認しました。本番にはテスト用残高を登録しません。本番の個人設定は所有者がアプリで入力します。

ニュース分析、購入候補、売却候補、含み損益の時価評価は、この台帳追加には含みません。価格・ニュースに基づく購入判断の検証は後続フェーズです。Cloudflare無料枠の継続稼働は引き続き確認が必要で、有料プランへの変更は行いません。

2026-09-26の本番配置で、マイグレーション適用、所有者認証後の台帳読み取り、未認証401、no-store、更新された画面の配信を確認しました。配置時の台帳は未登録で、既存の2銘柄の価格と定期取得設定も確認しています。台帳への実データ書き込みとAndroidでの新画面の操作は所有者の初回入力後に確認します。本番の台帳保存CPU時間・長期運用は未測定です。

Chromeでは、サーバーが保存した後の応答だけを遮断し、「同じリクエストで保存を再試行」で同一ID・同一内容を再送しても更新番号が1回だけ進むことも確認しました。
